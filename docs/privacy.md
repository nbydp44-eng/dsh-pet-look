# 隐私与数据流

这份文档说明 dsh-pet-look 到底看了什么、存了什么、什么时候把东西发出去。它是插件行为的事实说明，不是营销文案：做不到的地方会写「做不到」。

## 一句话版本

截图只存在于一次分析的几秒内；屏幕文字只在本地内存里过一遍；离开这台电脑的只有一张**已经裁到主屏、且在本地判断为不敏感**的截图，以及一段不含隐私的提示词。

## 数据流

```
主显示器 ──截图(PowerShell, 仅 PrimaryScreen)──► 临时 JPEG（%TEMP%/dsh-pet-look）
      │                                                   │
      │                                        本地 OCR + 关键词/PII 检测
      │                                                   │
      │                        ┌──────────────────────────┼───────────────┐
      │                     blocked                   redacted            ok
      │                        │                          │               │
      │                   删除截图，不上传          涂黑命中行后上传      直接上传
      │                                                   │               │
      └──────────────────────────────────────────► 视觉模型（你配置的那一个）
                                                          │
                                                返回 JSON（场景/是否说话/一句话/记忆）
                                                          │
                                          截图文件在 tempKeepSec（默认 300 秒）后删除；文本进气泡；记忆过敏感闸门
```

### 1. 截图范围

- 只截 `Screen.PrimaryScreen`，物理像素尺寸（PerMonitorV2 DPI 感知）。
- 不使用 `SystemInformation.VirtualScreen`，因此扩展屏不会被截进来。
- 不使用摄像头、麦克风、剪贴板、键鼠记录。

### 2. 截图的生命周期

| 阶段 | 位置 | 保留时间 |
| --- | --- | --- |
| 采集 | `%TEMP%\dsh-pet-look\shot-*.jpg` | 秒级 |
| 分析中 | 同上 + 附件服务的一份内存副本 | 一次请求 |
| 分析后 | 插件调用 `imageHostPath()` 删除宿主附件文件；临时 JPEG 默认保留 300 秒（`privacy.tempKeepSec`，可设 0）后删除，便于刚看到气泡就想追问时回看 | 0–300 秒 |

需要说清楚的限制：

- 宿主 `attachments` 服务**没有删除 API**。插件能删的是它写出的那个文件；如果宿主为压缩/转码生成过派生副本，那些副本可能留在宿主的附件目录里，插件无法定位、也无法保证清掉。
- 因此本插件**不承诺**「任何情况下磁盘上都没有痕迹」。能做到的是：不留历史截图、不把截图写进日志、不在重启后复用旧图。

### 3. 本地隐私门（fail closed）

识别顺序：凭据词整屏拦截 → 软词计数 → 证件/卡号/手机/邮箱定位并涂黑 → 命中行占比过高则整屏拦截。

- **凭据词**（密码、验证码、私钥、助记词、CVV、password、api key…）出现一次就整屏跳过。
- **软词**（支付、余额、银行、登录、账号…）累计 4 个才跳过——单独一个「支付」可能是视频标题，不该一票否决。
- **PII**（卡号、手机号、身份证、邮箱）命中行会被涂黑；涂黑后仍覆盖不到、或命中比例超过阈值，直接跳过。
- OCR 引擎不可用、脚本超时、返回异常 → 一律按「不安全」处理，不上传。

OCR 的结果**不出这台电脑**，也不写盘：脚本只回 `codes/keywords/hits` 这些判定结果，原始文字在进程内用完即弃。

### 4. 发给模型的内容

- 一张 JPEG（宽 ≤ `vision.maxWidth`，默认 1600）。
- 一段提示词：前台应用名、场景参考、当前时间、长期记忆条目、最近说过的话。
- 不发：完整 OCR 文本、窗口标题全文、剪贴板、文件路径。

模型供应商是否会留存你上传的图片，**由供应商决定，插件无法控制**。请只配置你信任的、明确知道其数据政策的视觉服务。

### 5. 绝不发生的事

- 不把截图发给内置推荐列表里的匿名/免费聚合渠道（`free|anonymous|ovh|kilo|g4f|pollinations|chatanywhere|gpt4free|duckduckgo` 一律跳过）。
- 不为插件购买任何 API 或产生费用；没有可用视觉服务时，插件只保留截图/隐私/菜单能力，不猜、不降级到别的服务。
- 不把屏幕文字、OCR 结果、聊天内容写进日志。
- 不保存历史截图。

### 6. 日志里到底有什么

`logs/look-YYYY-MM-DD.jsonl`，每行只有四个字段：

```json
{"t":"2026-11-04T01:47:02.331Z","ok":true,"ms":6403,"code":"manual-ok"}
```

`code` 是固定枚举（`spoke`/`quiet`/`privacy-blocked`/`vision-no-vision-route`…），不含任何正文。日志保留 7 天，启动时清理更早的文件。

### 7. 记忆

- 只存三类事实：正在做的任务、学习/工作进度、反复出现的兴趣。
- 入库前二次过滤：含 6 位以上连续数字、或凭证/身份/支付词的内容直接拒绝。
- 上限 120 条，超出淘汰最旧的；用户可在设置页查看与一键清空。
- 记忆里没有屏幕原文，只有模型概括的一句话。

### 8. 用户能关到什么程度

| 想要的效果 | 做法 |
| --- | --- |
| 完全不上传 | 设置页关闭「自动识屏」，并把 `vision.provider/model` 留空且不要配置任何视觉服务；插件会记 `vision-no-vision-route` 并停止调用 |
| 不上传、但保留手动看一眼 | 关闭自动识屏，仅在需要时右键「立即识屏」 |
| 只在自己主动时说话 | 设置页把「每小时最多」设为 1，间隔设为最大 |
| 完全静音 | 关闭自动识屏，并取消勾选「记忆」；菜单里的「自动识屏：暂停」会停止一切截图 |

## 已知边界（不要当成已解决）

1. 附件服务的派生副本无法由插件删除（见 §2）。
2. OCR 是启发式，不是保证。涂黑只覆盖识别到的文字行，图片里的密码、二维码、验证码图形无法识别。
3. 视觉供应商的上游留存不可控。
4. 「用户是否回复过」只能通过桌宠聊天记忆文件的修改时间近似判断，不是精确的对话状态。
5. 只在 Windows 上验证过；其他平台没有实现截图后端。

## 本机 HTTP 接口

| 路由 | 方法 | 作用 | 返回 |
| --- | --- | --- | --- |
| `/dsh-pet-look/status` | GET | 运行状态 | 无屏幕内容 |
| `/dsh-pet-look/settings` | GET | 设置页 HTML | 无外链 |
| `/dsh-pet-look/settings` | POST | 保存设置 | 白名单字段 |
| `/dsh-pet-look/settings/state` | GET | 设置页读当前值 | 无屏幕内容 |
| `/dsh-pet-look/persona` | GET/POST | 读写人设 | 仅人设字段 |
| `/dsh-pet-look/trigger` | POST | 手动触发一次识别 | 不返回画面 |
| `/dsh-pet-look/toggle` | POST | 开/停自动识屏 | 布尔 |
| `/dsh-pet-look/memory` | DELETE | 清空记忆 | 计数 |
| `/dsh-pet-look/logs` | GET | 最近 200 行日志 | 仅四个字段 |

这些接口都不是数据出口：没有任何一条会把截图、OCR 文字或聊天内容返回给调用方。

防护：Host 必须是回环名（防 DNS rebinding）；跨站 `Origin` / `Sec-Fetch-Site` 一律 403；写操作必须是 `application/json`；请求体上限 8 KB；字段白名单 + 数值夹取。
没有做令牌认证——同用户的本地进程本来就能读这些文件，自制认证只增加复杂度。
