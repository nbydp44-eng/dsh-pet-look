# 设计说明（0.2.0）

## 定位

一句人话：**屏幕内容决定说什么，人设决定怎么说，场景和时间决定什么时候说。**

不是「定时截图 + 定时提醒」。时间、应用类型、连续使用时长都只是辅助上下文，不能替代对画面内容的理解，也不能直接翻译成「该提醒休息了」。

## 说话决策链

```
截图 → dHash 变化? ──否──► 结束（记 unchanged）
          │是
    隐私门 ──blocked──► 结束（不上传、不记忆）
          │ok/redacted
    场景判断（chat/payment → 静音）
          │
    模型输出 {scene, speak, text, stuck, confidence, memory}
          │
    置信度门槛（人设微调 ±0.2）→ 频率上限（3/小时、15 分钟）→ 重复闸门 → 气泡
```

四个闸门缺一不可：内容、场景、频率、重复。任何一条不过就不说。

## 人设模型

- 预设 5 个：`companion / humor / analyst / chatty / observer`。
- 自定义 3 个字段：性格描述（300 字）、称呼（8 字）、禁止话题（120 字）。
- `speakBias` 只调置信度门槛（安静观察 −0.2，活泼健谈 +0.12），**不调频率上限**——用户设的限制永远优先。
- 人设文本只拼进提示词的【人设】段；硬规矩（只谈内容、不劝睡、不重复、≤35 字）单独成段，排在后面，且不来自用户输入。

为什么不用「用户写一段 Prompt」：普通用户写不出稳定的人设，也容易写出会覆盖隐私与频率约束的指令。结构化字段 + 固定规矩更可控。

## 设置入口

右键菜单「设置面板」→ 用默认浏览器打开 `http://127.0.0.1:<port>/dsh-pet-look/settings`。

- 页面由插件自己的 HTTP 路由渲染，单文件、无外链、无 CDN、无第三方脚本。
- 保存走 `POST /dsh-pet-look/settings`，即时写入运行时，不重启。
- 只暴露常用项；高级项（provider/model、阈值、日志）仍留在配置文件。

为什么不做客户端 UI 面板：需要引入 client bundle 与 Slot 注册，维护成本高；本机网页已经覆盖「普通用户能改」的全部内容，且天然在 DSH 的 127.0.0.1 同源下。

## 默认值取舍

| 项 | 默认 | 理由 |
| --- | --- | --- |
| 自动识屏 | 开 | 装了就是要用；但频率保守 |
| 间隔 | 60s（电池 180s） | 够理解上下文，又不至于频繁 |
| 主动发言 | 3 次/小时、间隔 15 分钟 | 明显低于「打扰」阈值 |
| 夜间安静 | 关 | 用户明确讨厌被管作息，但也可能想夜里被陪；交给用户开 |
| 记忆 | 开 | 只存任务与进度，且有二次敏感闸门 |
| 视觉服务 | 自动挑已配置的 | 不新增费用、不引入新供应商 |

## 通用性

同一份代码覆盖学生/办公/开发/游戏/视频/轻度/隐私敏感：差异全部收敛到「人设 + 频率 + 开关」三个维度，不为人群分叉代码。

隐私敏感用户的完整关闭路径：关自动识屏 → 插件不截图；或干脆不配置视觉服务 → 插件只做本地能力并记 `vision-no-vision-route`。

## 兼容性影响

- 需要 `dsh-pet` 的第三方菜单 API（0.3+），不依赖其 `renderer.js`。
- 依赖宿主 `llm` 与 `attachments` 服务；缺失时降级为「只截图 + 只菜单」，不崩溃。
- 升级 0.1.x → 0.2.0：旧人设 key 自动映射，配置无需迁移。
- 不改 DSH 核心、不改原桌宠、不写注册表。

## 明确不做

- 不做定时提醒/健康管理。
- 不做多屏拼接、不做摄像头/麦克风。
- 不内置任何视觉服务或密钥。
- 不做云同步、不收集遥测。
